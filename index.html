02

Motivation

Demographic inference from genealogies

  • Goal: compute the probability of a genealogy given a demographic model
$$P(G \mid \theta)$$
  • \(G\): genealogical tree
  • \(\theta\): demographic model
  • Genealogies encode
    • population sizes
    • admixture events
    • migration history
  • ARG inference makes genealogy-based approaches computationally feasible.
  • We seek a likelihood framework for demographic inference.
03

Biological Setting

What does a genealogy encode?

  • Genealogies summarize shared ancestry among sampled chromosomes.
  • Each internal node represents a coalescence event (most recent common ancestor).
  • Branch lengths record the time between coalescence events.
Population size shapes genealogies
  • Small populations → rapid coalescence → shorter branches
  • Large populations → slower coalescence → longer branches
  • In structured populations, each lineage also has a population assignment.
  • Migration changes these assignments through time.
  • Together, genealogy and lineage locations encode:
    • effective population size
    • population structure
    • migration history

Genealogy of four sampled chromosomes from two populations. Branch lengths reflect coalescence times, while migration changes lineage population assignments through time.

04

gLike (Fan et al. 2025)

Genealogical likelihood framework

Given:

  • tree topology and coalescence times
  • leaf population labels
  • demographic model

Unknown:

  • population memberships of internal lineages

Compute

$$P(G \mid \theta)$$

by integrating over all admissible lineage histories.

05

Graph of States

Central object: Graph of States (GOS)

A state is an assignment of every active lineage to a population:

$$\mathbf{s} = (p_1, p_2, \ldots, p_n), \quad p_i \in \{1, \ldots, K\}$$

Biologically: which present-day deme is each ancestral chromosome currently residing in?

Technical motivation: between coalescence events, lineages migrate according to migration matrix \(M\). The GOS encodes which configurations are reachable and with what probability, so we can sum over all lineage histories without enumerating trajectories explicitly.

Algorithm:

  • identify possible lineage populations at each epoch
  • construct GOS — nodes are states, edges are migration/coalescence events
  • compute conditional probabilities along branches (matrix exponential)
  • propagate marginal probabilities forward in time
  • sum over root states

Each node is a population assignment; edges are migration transitions weighted by \(e^{M\delta t}\).

Exact likelihood No trajectory enumeration Accurate for pulse admixture
06

Limitation

Continuous migration

Suppose migration is described by a rate matrix

$$M(t)$$
  • lineages may migrate at every instant
  • configurations communicate continuously
  • the graph of states becomes intractable

The number of configurations grows as

$$K^n$$
Concrete scale: with \(K = 5\) populations and \(n = 10\) lineages, that is nearly 10 million states. With \(K = 10, n = 20\) it is \(10^{20}\).

Question

Can we integrate over continuous lineage trajectories without enumerating states?

Biological motivation: Real populations do not exchange migrants in discrete pulses. Dispersal is continuous — isolation by distance, range expansions along river systems, gene flow across a cline. A model with a continuous migration rate matrix \(M(t)\) is the natural description of these processes.

07

The Biology of Continuous Migration

Why model migration with a rate matrix \(M(t)\)?

  • Migration is typically an ongoing process, not a series of discrete events.
  • \(M_{jk}\) denotes the instantaneous rate that a lineage moves from population \(j\) to population \(k\).
  • This framework naturally accommodates changing migration rates through time.
Examples
  • Isolation by distance — migration is highest between neighboring populations.
  • Range expansion — migration is directional as populations colonize new regions.
  • Secondary contact — previously isolated populations exchange migrants after reconnecting.
  • These scenarios are difficult to represent with pulse admixture alone.
  • A continuous migration model provides a more realistic description of lineage movement.

Continuous migration is represented by a rate matrix. Nearby populations exchange migrants more frequently than distant populations, producing spatial population structure over time.

08

Structured Coalescent Likelihood

$$L = \sum_x P(x \mid \mathrm{mig}) \prod_a \delta_{x_a, k_a} \prod_s \frac{1}{2N_{x_s}(t_s)} \exp\!\left(-\int \lambda(t;\,x)\,dt\right)$$

where

$$\lambda(t;\,x) = \sum_k \frac{1}{2N_k(t)} \binom{\ell_k(t;\,x)}{2}$$

Reading the formula: \(x\) is a complete trajectory assigning each lineage to a population at every moment. \(\lambda(t;x)\) is the total coalescence rate given those assignments — it sums over populations the rate at which pairs of lineages in that population coalesce. The exponential is the probability of no coalescence between recorded events (survival term).

Difficulty

Integrating over all trajectory assignments \(x\) — this is a sum over uncountably many continuous paths.

09

Main Idea

$$L = L_{\mathrm{peel}} \cdot E_Q\!\left[e^{-\int \lambda\,dt}\right]$$

This decomposition is exact.

Pass I

Compute \(L_{\mathrm{peel}}\) via Felsenstein pruning — a backward pass that integrates over migration using the transition matrix.

Pass II

Approximate the survival term \(E_Q[e^{-\int \lambda\,dt}]\) without constructing a graph of states — instead, track low-order moments of the lineage location distribution.

10

Backward Pass

Felsenstein pruning under the structured coalescent

$$L_a(k,\,t) = P(\text{subtree below }a \mid a \in k)$$
Leaf initialization
$$L_a(k) = \delta_{k,\,k_a}$$

A leaf in population \(k_a\) has probability 1 of being there, 0 elsewhere.

Branch propagation
$$\tilde{L}_a(j) = \sum_k T_{jk}(\delta)\,L_a(k)$$

Smear the likelihood up the branch via the migration transition matrix \(T = e^{M\delta}\).

Coalescence merge
$$L_c(k) = \frac{1}{2N_k}\,\tilde{L}_a(k)\,\tilde{L}_b(k)$$

Two lineages coalesce in population \(k\) at rate \(1/2N_k\); both must be in the same deme.

Output: \(L_{\rm peel}\)  ·  Complexity: \(O(nK^2)\)

11

Why a Second Pass?

  • Backward pass gives $$P(\text{descendants} \mid \text{location})$$
  • Contains no information about ancestry above a node.
  • Need $$P(\text{location} \mid \text{ancestral history})$$
  • Hence a forward pass is required.

Biological intuition: The backward pass asks "given where this lineage is, what is the probability of the observed descendants?" But to compute the coalescence survival term we need to know, for each pair of lineages, how likely they are to be in the same deme at the same time — information about their joint location history, which depends on where they came from.

12

Biological Intuition: The Two Passes

How the forward and backward passes complement one another

Pass I — Backward (leaves → root)
  • Starts from the observed samples.
  • Evaluates which ancestral population assignments are most consistent with the genealogy.
  • Computes $$L_a(k,t)=P(\text{descendants}\mid a\in k).$$
  • Provides the likelihood contribution from each subtree.
Pass II — Forward (root → leaves)
  • Propagates ancestral population distributions through time.
  • Tracks pairwise lineage locations: $$\Pi_{ab}(j,k;t).$$
  • Captures correlations introduced by shared ancestry and migration.
  • Determines where lineages are expected to co-occur.

Why both passes?

  • Backward pass: How well does a population assignment explain the observed genealogy?
  • Forward pass: Where are ancestral lineages expected to be through time?
  • Combining both produces the posterior probability that two lineages occupy the same population.
  • This posterior determines the expected coalescence rate used in the survival term.

The forward pass provides a prior over lineage locations, while the backward pass provides the likelihood of the observed genealogy. Their combination yields the posterior distribution used to compute expected coalescence rates.

13

Forward Pass

Pairwise location priors

Track marginals

$$\pi_{a,k}(t) = P(\text{lineage }a\text{ in pop }k\text{ at time }t)$$

Track pairwise moments

$$\Pi_{ab}(j,k;\,t) = P(\text{lin. }a\text{ in }j,\;\text{lin. }b\text{ in }k\text{ at }t)$$

Evolution equations:

$$\pi_a(t+\delta) = \pi_a(t)\,T(\delta)$$
$$\Pi_{ab}(t+\delta) = T^{\!\top}\,\Pi_{ab}(t)\,T$$

Why pairwise moments? The coalescence rate depends on pairs of lineages co-locating in the same deme. A single marginal \(\pi_{a,k}\) cannot capture correlations between two lineages — we need the joint distribution \(\Pi_{ab}\).

Complexity: \(O(n^2 K^2)\) — quadratic in lineage count because we track all pairs, quadratic in population count for the matrix multiplications.

14

Combining Both Passes

$$\gamma_{ab}(j,k;\,t) \;\propto\; \Pi_{ab}(j,k;\,t)\;L_a(j,t)\;L_b(k,t)$$

Posterior co-location probability:

$$c_{ab,k}^{(\mathrm{post})}(t) = \sum_j \gamma_{ab}(j,k;\,t)\,\mathbf{1}[j=k]$$

Expected coalescence rate:

$$E_Q[\lambda(t)] = \sum_{a < b}\sum_k \frac{c_{ab,k}^{(\mathrm{post})}(t)}{2N_k(t)}$$

Interpretation: \(\gamma_{ab}\) combines two sources of evidence — the forward pass tells us where the lineages are likely to be (prior from ancestors), the backward pass tells us what that implies for descendants (likelihood). Their product, normalized, is the posterior.

Integrating \(E_Q[\lambda(t)]\) gives the expected total coalescence opportunity — the key ingredient in the survival term.

15

Mean-Field Approximation

Only approximation in the algorithm

$$E_Q\!\left[e^{-\int\lambda\,dt}\right] \;\approx\; \exp\!\left(-\int E_Q[\lambda(t)]\,dt\right)$$

Therefore

$$\log L = \log L_{\rm peel} - \int E_Q[\lambda(t)]\,dt$$

Everything else is exact.

Why approximation is needed: The survival term \(E[e^{-\int\lambda\,dt}]\) is the moment-generating function of an integral of a continuous-time Markov chain. No closed form is known in general — exact computation would require the full joint distribution over all lineage trajectories, i.e., the intractable GOS.

Quality of the approximation: This is Jensen's inequality applied to the convex function \(e^{-x}\), so the approximation is a lower bound on the true \(E[e^{-\int\lambda\,dt}]\). The gap is controlled by the variance of \(\int\lambda\,dt\) under \(Q\).

Ways to improve: Higher-order cumulant corrections — using triplet moments (third-order) gives a tighter bound. Cumulant expansion: \(\log E[e^{-X}] \approx -\kappa_1 + \tfrac{1}{2}\kappa_2 - \cdots\) where \(\kappa_i\) are cumulants of \(\int\lambda\,dt\).

Mean-field is easy to implement — the result is a simple integral over the expected rate, computable in a single forward-backward sweep with no additional data structures.
